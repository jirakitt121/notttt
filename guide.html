Nut Inspect — SQLite + OOP + Workflow

ชุดประกอบโปรเจกต์ อ้างอิงโค้ดเว็บ Nut Inspect วันที่ 3 กันยายน 2026

เริ่มจากไฟล์ไหน

  • แตก ZIP ก่อน แล้วเปิด guide.html ด้วย Chrome หรือ Edge เพื่ออ่านคู่มือและดูผัง
  • ดู diagrams/workflow.png, oop.png และ er.png เพื่อนำไปใส่รายงานหรือสไลด์ มี SVG สำหรับขยายภาพ และ Mermaid .mmd สำหรับแก้ไขผัง
  • database/nut-inspect-empty.sqlite เป็นฐานข้อมูล SQLite จริง 13 ตาราง แต่ไม่มีข้อมูลผู้ใช้ รหัสผ่าน คีย์ รูปภาพ หรือผลตรวจจริง
  • database/schema.sql ใช้สร้างฐานข้อมูลใหม่ที่มีโครงสร้างเดียวกัน ห้ามนำไปรันเป็น migration ทับฐานข้อมูลเว็บจริง
  • oop/parts.ts คือคลาสที่ API จัดการน็อตของเว็บใช้จริง ส่วน oop/parts.mjs เป็นโค้ดชุดเดียวกันที่แปลงให้รันทดลองด้วย Node.js

นี่ไม่ใช่ไฟล์สำรองข้อมูลจริง และไม่ใช่ ZIP ของเว็บทั้งโปรเจกต์ การเปิดไฟล์ SQLite ในเครื่องจะไม่เชื่อมต่อหรือแก้ไขข้อมูลบนเว็บไซต์

ทดลอง OOP โดยไม่ใช้ API Key

ใช้ Node.js รุ่น 22.13 ขึ้นไป ไม่ต้อง npm install สำหรับชุดทดลองนี้

เปิด Terminal ในโฟลเดอร์ที่แตก ZIP แล้วรัน:


node oop/demo.mjs

node tests/test_bundle.mjs

คำสั่งแรกจะสร้าง nut-inspect-demo.sqlite ข้างคู่มือ และเพิ่มน็อตตัวอย่าง 1 รายการในโหมดสาธิต ไม่มีภาพหรือผลตรวจจำลอง ไม่แตะไฟล์ฐานข้อมูลว่าง หากไฟล์สาธิตมีอยู่แล้ว คำสั่งจะหยุดโดยไม่เขียนทับ

คำสั่งทดสอบใช้ฐานข้อมูลชั่วคราว ตรวจการเพิ่ม/แก้ไข รหัสซ้ำ ข้อมูลสาธิตแยกจากข้อมูลจริง และความคงอยู่หลังเปิดฐานข้อมูลใหม่ ไม่เชื่อมต่ออินเทอร์เน็ต

SQLite ของเว็บจริงอยู่ตรงไหน

เว็บออนไลน์ใช้ D1 ซึ่งมีเอนจิน SQLite ฝั่งเซิร์ฟเวอร์ ไม่ได้เก็บฐานข้อมูลหลักไว้ในมือถือ เครื่องของผู้ใช้ส่งคำขอให้เซิร์ฟเวอร์อ่าน/บันทึกฐานข้อมูล ส่วนโมเดล ONNX ตรวจภาพในเบราว์เซอร์

ไฟล์ว่างนี้สร้างจาก migrations/0001_initial.sql และ drizzle/*.sql ของเว็บ โดยใช้ฐานข้อมูลในหน่วยความจำเพื่อรวมโครงสร้างหลัง migration ไม่ได้ดาวน์โหลดฐานข้อมูลจริง ไม่มีการแก้ schema ของเว็บในงานรอบนี้

ตารางหน้าที่
partsรหัส ชื่อ ขนาด วัสดุ Lot และหมายเหตุน็อต
inspectionsภาพที่บันทึก พร้อมข้อมูลน็อต ณ เวลานั้น และสถานะผู้ตรวจ
runsผลตรวจแต่ละครั้ง โมเดล ค่า confidence กล่องตำแหน่ง และไฟล์ภาพผลตรวจ
reviewsประวัติการยืนยัน PASS/FAIL/รอยืนยัน
stored_filesชนิดและขนาดของไฟล์ที่เก็บ
file_chunksเนื้อไฟล์แบ่งเป็นชิ้นและเก็บแบบ base64 ตามโค้ดปัจจุบัน
settingsการตั้งค่า เช่น โมเดลจริง
model_uploadsข้อมูลการอัปโหลดโมเดลที่ยังดำเนินการอยู่
demo_itemsระบุว่าน็อตหรือภาพใดเป็นข้อมูลสาธิต
admin_accountsข้อมูลบัญชีแอดมินและค่าที่ใช้ตรวจรหัสผ่าน (ไฟล์นี้ไม่มีบัญชี)
admin_sessionsเซสชันแอดมินแบบเก็บค่าแฮช (ไฟล์นี้ไม่มีเซสชัน)
chat_threadsหัวข้อสนทนาและเจ้าของ
chat_turnsคำถาม คำตอบ และสถานะการตอบ

ดูชนิดข้อมูล คอลัมน์ Primary Key, Foreign Key และดัชนีครบทุกตารางได้ใน database/data-dictionary.json และในคู่มือ HTML

OOP ที่นำไปใช้จริง

งานรอบนี้จัดส่วน จัดการรายการน็อต เป็น OOP ไม่ได้อ้างว่าทั้งเว็บถูกเขียนใหม่เป็นคลาส

องค์ประกอบหน้าที่จุดที่แสดงหลัก OOP
Partรับและตรวจค่ารหัส/ชื่อ/ขนาด/วัสดุ/Lot/หมายเหตุEncapsulation: ซ่อนค่าภายในและคืนสำเนาค่า
PartServiceอ่าน เพิ่ม และแก้ไขรายการ พร้อมจัดการรหัสซ้ำและรายการไม่พบComposition: รับ repository, ตัวสร้าง ID และนาฬิกาผ่าน constructor
PartStoreสัญญาเมธอด list/find/insert/updateAbstraction: service ไม่ต้องรู้ SQL หรือผู้ให้บริการฐานข้อมูล
SqlitePartRepositoryใช้ prepared statements และ batch กับฐานข้อมูลImplementation ของ PartStore; ไม่ต่อข้อความที่กรอกเข้า SQL
LocalSqliteDatabaseตัวแปลงฐานข้อมูล SQLite ในเครื่องให้ตรงกับ Database interfacePolymorphism: ใช้คลาสธุรกิจเดียวกับ D1 โดยเปลี่ยน adapter
HttpErrorข้อผิดพลาดที่มี HTTP statusInheritance: extends Error; API ยังคงจัดรูปแบบข้อผิดพลาดเดิม

PartStore และ Database เป็น TypeScript interface ไม่ใช่ตาราง SQL และไม่ใช่คลาสที่สร้าง object ด้วย new ได้ ส่วน Detector ใน Python เป็นอีกเวอร์ชันสำหรับรันในเครื่อง ไม่ใช่โมเดลที่เว็บออนไลน์เรียกใน workflow นี้

ตัวอย่างโค้ดจากเส้นทางที่เว็บใช้:


const service = new PartService(new SqlitePartRepository(db));

const saved = await service.save(input, 'create', 'real');

จุดเชื่อมจริงอยู่ที่ worker/api.ts ในสาขา /api/parts โดย worker/index.ts ตรวจสิทธิ์แอดมินก่อนเข้า API ตามเดิม ตัวอย่างใน ZIP เรียกคลาสโดยตรงเพื่อสาธิต OOP ไม่ใช่เว็บเซิร์ฟเวอร์ที่เปิดให้ผู้อื่นเรียกได้

Workflow และข้อควรระวัง

  • เริ่มจากการยืนยันเจ้าของเว็บและล็อกอินแอดมิน ผู้ไม่ผ่านสิทธิ์ไม่ควรเข้าถึง API หรือรูปภาพ
  • เลือกโหมดจริง/สาธิตก่อนทำงาน ภาพสาธิตไม่ใช่หลักฐานคุณภาพชิ้นงานจริง
  • บันทึกภาพได้แม้ไม่มีโมเดล โดยคงสถานะรอตรวจ ไม่ใช่ศูนย์ตำหนิหรือ PASS
  • เมื่อโมเดลพร้อม ผู้ใช้กดตรวจในเบราว์เซอร์ แล้วเซิร์ฟเวอร์ตรวจรูปแบบผลลัพธ์และบันทึกผล ไม่ใช่การรัน inference ซ้ำบนเซิร์ฟเวอร์
  • not_detected คือไม่พบคลาสตำหนิที่เลือก ไม่ใช่การรับรองว่าชิ้นงานผ่านมาตรฐาน
  • PASS/FAIL เป็นการยืนยันของผู้ตรวจ แยกจากผลโมเดล หากตรวจใหม่สถานะยืนยันจะกลับไปรอ แต่ประวัติเดิมยังเก็บอยู่
  • ผู้ช่วยแชทอ่านคู่มือและข้อมูลที่บันทึกไว้ ไม่ต้องใช้ API Key ไม่ตรวจภาพหรือแก้ไขข้อมูลแทนผู้ใช้

ขอบเขตผังฐานข้อมูล

ผัง ER แสดงความสัมพันธ์ Foreign Key ที่ schema บังคับจริง 4 เส้น: parts → inspections, inspections → runs, inspections → reviews และ chat_threads → chat_turns

ความสัมพันธ์ไฟล์ ภาพ ข้อมูลสาธิต และเจ้าของเซสชันบางส่วนควบคุมด้วยโค้ด ไม่ได้ประกาศ Foreign Key ใน schema ปัจจุบัน จึงแสดงเป็นหมายเหตุแยก ไม่วาดให้เข้าใจผิดว่าฐานข้อมูลบังคับให้

ผลทดสอบ

ดู VALIDATION.md สำหรับรายการทดสอบและข้อจำกัด ชุดนี้ไม่ได้ให้ค่าความแม่นยำของโมเดลจริง เพราะยังไม่มีโมเดลที่เทรนกับชิ้นงานจริงของคุณ

ดัชนี inspections_part ถูกใช้ใน query plan ที่ทดสอบผ่าน
OOP: ตรวจข้อมูล ซ่อนค่า และเปลี่ยน store สำหรับทดสอบผ่าน
เพิ่ม แก้ไข อ่าน รหัสซ้ำ และรายการไม่พบผ่าน

ข้อมูลคงอยู่หลังปิดและเปิด SQLite ใหม่ผ่าน
API เดิม: รูปภาพ snapshot ข้อมูลน็อต รีวิว CSV/ZIPผ่าน
แอดมิน: รหัสผ่าน เซสชัน สิทธิ์ CSRF และออกจากระบบผ่าน
แชทไม่ใช้คีย์: แหล่งข้อมูล ขอบเขต ประวัติ และกรณีผิดพลาดผ่าน
ชุดส่งมอบแยกโฟลเดอร์ (node tests/test_bundle.mjs)ตัวจัดแพ็กเกจตรวจและยอมสร้างชุดส่งมอบต่อเมื่อผ่าน

วิธีทดสอบซ้ำ

ในโปรเจกต์เต็ม ใช้ npm run check, npm run test:architecture และ npm run test:api

ใน ZIP นี้ ใช้ node tests/test_bundle.mjs โดยต้องมี Node.js 22.13 ขึ้นไป ไม่ต้องติดตั้ง package เพิ่ม และไม่เชื่อมต่อบริการภายนอก

ข้อจำกัด

  • ใช้ข้อมูลทดสอบและฐานข้อมูลชั่วคราว ไม่ทดสอบด้วยบัญชี/ข้อมูลการตรวจจริงของผู้ใช้
  • ไม่ได้ทดสอบผ่านเบราว์เซอร์หรืออุปกรณ์จริงในรอบนี้
  • ผัง PNG ตรวจการจัดวางและความอ่านง่ายแล้ว ไม่ใช่ภาพหน้าจอเว็บ
  • ยังไม่ได้วัดความแม่นยำกับโมเดลที่ผู้ใช้เทรนจริง และไม่ได้เพิ่มโมเดลตรวจชิ้นงานจริง
  • งานนี้เปลี่ยนโครงสร้างโค้ดส่วนรายการน็อต ไม่มี migration ใหม่ ไม่มีการย้ายหรือลบฐานข้อมูลเว็บ
  • SQLite ใน ZIP ไม่ซิงก์กับ D1 และไม่ใช่ระบบล็อกอินหรือเว็บเต็มที่พร้อม deploy แยกต่างหาก
